## Goal

Implement complete vault indexing with semantic embedding and Orama vector storage, triggered by the existing ribbon icon with user confirmation and progress feedback.

## Requirements

### Functional Requirements

| ID | Requirement |
|----|-------------|
| FR-01 | The plugin must scan all markdown notes in the Obsidian vault. |
| FR-02 | Each note must be split into semantic chunks of approximately 500 tokens with 100-token overlap between adjacent chunks. |
| FR-03 | Each chunk must be embedded via an OpenAI-compatible embedding endpoint at `http://localhost:10001` using model `v5-small-retrieval-Q8_0.gguf`. |
| FR-04 | Embeddings must be stored in an Orama vector store file located inside the Obsidian vault. |
| FR-05 | Clicking the Yggdrasil ribbon icon must trigger a full reindex: clear all existing vectors and rebuild from scratch. |
| FR-06 | Before starting a reindex, a confirmation modal must be shown to the user. |
| FR-07 | During indexing, the user must receive progress updates via Obsidian `Notice` (e.g., "Indexing note 15 of 120..."). |
| FR-08 | Upon completion, a final notice must confirm success or report any errors. |
| FR-09 | The embedding endpoint URL and model name are hard-coded for this version (no user configuration UI). |

### Non-Functional Requirements

| ID | Requirement |
|----|-------------|
| NFR-01 | Indexing must not block the Obsidian UI thread for more than a few hundred milliseconds at a time (use batching or async processing). |
| NFR-02 | Embedding calls must include a per-request delay of at least 100ms to avoid overwhelming the LiteLLM proxy. |
| NFR-03 | The Orama vector store must be stored as a JSON file inside the vault plugin directory (e.g., `.obsidian/plugins/yggdrasil/vectors.json`). |
| NFR-04 | Non-markdown files (images, PDFs, etc.) must be silently skipped during indexing. |
| NFR-05 | Empty or unreadable files must be silently skipped (logged to console, no crash). |

## Scope

### In-scope
- Vault scanning for markdown files
- Note chunking (500 tokens / 100-token overlap)
- Embedding via OpenAI-compatible API (LiteLLM → llama.cpp)
- Orama vector storage inside the vault
- Full reindex via ribbon icon with confirmation and progress
- Error handling for network failures, API errors, and file read errors

### Out-of-scope
- Incremental indexing (add/modify/delete individual notes)
- Search/query functionality (will be PRD 001.02)
- User configuration UI for endpoint/model settings
- Support for non-markdown attachments (PDFs, images)
- Metadata filtering or faceted search
- On-device embedding (local model)

## Context

Yggdrasil is an Obsidian plugin providing RAG-powered AI assistance for dungeon masters and world-builders. This is the first major feature after the initial plugin scaffold. Orama (`@orama/orama`) is already a dependency. The embedding infrastructure is a LiteLLM proxy (`http://localhost:10001`) routing to a llama.cpp-hosted embedding model (`v5-small-retrieval-Q8_0.gguf`). The existing ribbon icon currently shows a simple "Yggdrasil is ready!" notice — it will be repurposed to trigger indexing.

## Technical Specification

### Files to Create

| File | Purpose |
|------|---------|
| `src/rag/chunker.ts` | Note chunking logic (token-aware splitting with overlap) |
| `src/rag/embedder.ts` | Embedding client using Obsidian `requestUrl()` (NOT LanceDB's OpenAIEmbeddingFunction — it does not support custom base URLs) |
| `src/rag/vector-store.ts` | Orama wrapper (create/open, insert, search, clear, save/load) |
| `src/rag/indexer.ts` | Orchestrator: scan vault → chunk → embed → store |
| `src/main.ts` | Update ribbon icon handler to trigger reindex |

### Architecture Decision: Custom Embedder

LanceDB's built-in `OpenAIEmbeddingFunction` was evaluated but rejected because:
- It hardcodes the OpenAI API endpoint and does not support custom base URLs.
- The `openai` npm package is not a dependency and would add unnecessary bloat.
- Obsidian's `requestUrl()` provides a lightweight, built-in alternative for HTTP calls.

The custom embedder in `embedder.ts` will use `requestUrl()` to POST to the LiteLLM proxy endpoint.

### Orama Schema

```json
{
  "id": "string",
  "text": "string",
  "source": "string",
  "chunkIndex": "number",
  "embedding": "vector[1024]"
}
```

### Schema Creation Strategy

The embedding dimension is hard-coded to 1024 (matching `v5-small-retrieval-Q8_0.gguf`). This will become a configurable setting in a future PRD.

1. Create a new Orama database with the schema above.
2. Insert all chunks using `insertMultiple`.
3. Persist the database to disk via `save()` which serializes to JSON.

### Embedding API Contract

- Endpoint: `POST http://localhost:10001/v1/embeddings`
- Request body:
  ```json
  {
    "model": "v5-small-retrieval-Q8_0.gguf",
    "input": ["chunk text here"],
    "encoding_type": "float"
  }
  ```
- Response: standard OpenAI-compatible embeddings response with `data[].embedding` array.
- Batch size: embed up to 100 texts per request (OpenAI API limit) for efficiency.

### Chunking Strategy

1. Read file content as text.
2. Split by double-newline (paragraph boundary) as primary split point.
3. Accumulate paragraphs into chunks until ~500 tokens is reached.
4. If a single paragraph exceeds 500 tokens, split by sentence boundary.
5. Each chunk stores its 100-token overlap suffix as context for the next chunk.

### Error Handling

- Network errors during embedding: skip the chunk, log error, continue with next.
- API errors (4xx/5xx): log error, continue.
- File read errors: skip file, log to console.
- Vector store errors: show error notice, abort reindex.
- Per-request delay (100ms): applied between embedding API calls.
- Embedding dimension mismatch (response not 1024): abort with clear error message.

### Progress Reporting

- Notice is updated every N notes (e.g., every 5 notes) with format: `"Indexing: 15/120 notes"`
- Final notice: `"Indexing complete: 120 notes indexed"` or `"Indexing failed: <error message>"`

### Orama Operations

| Operation | Method |
|-----------|--------|
| Create database | `create({ schema: { id: "string", text: "string", source: "string", chunkIndex: "number", embedding: "vector[1024]" } })` |
| Open existing | `load(oramaInstance, rawData)` from saved JSON |
| Clear all rows | Fulltext search for all hits, then `remove` each |
| Insert data | `insertMultiple(oramaInstance, docs)` |
| Save to disk | `save(oramaInstance)` → `JSON.stringify` → write to file |
| Load from disk | `JSON.parse` file → `load(oramaInstance, rawData)` |
