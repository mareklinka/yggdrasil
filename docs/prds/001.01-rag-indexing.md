## Goal

Implement complete vault indexing with semantic embedding and LanceDB vector storage, triggered by the existing ribbon icon with user confirmation and progress feedback.

## Requirements

### Functional Requirements

| ID | Requirement |
|----|-------------|
| FR-01 | The plugin must scan all markdown notes in the Obsidian vault. |
| FR-02 | Each note must be split into semantic chunks of approximately 500 tokens with 100-token overlap between adjacent chunks. |
| FR-03 | Each chunk must be embedded via an OpenAI-compatible embedding endpoint at `http://localhost:10001` using model `v5-small-retrieval-Q8_0.gguf`. |
| FR-04 | Embeddings must be stored in a LanceDB database file located inside the Obsidian vault. |
| FR-05 | Clicking the Yggdrasil ribbon icon must trigger a full reindex: clear all existing vectors and rebuild from scratch. |
| FR-06 | Before starting a reindex, a confirmation modal must be shown to the user. |
| FR-07 | During indexing, the user must receive progress updates via Obsidian `Notice` (e.g., "Indexing note 15 of 120..."). |
| FR-08 | Upon completion, a final notice must confirm success or report any errors. |
| FR-09 | The embedding endpoint URL and model name are hard-coded for this version (no user configuration UI). |

### Non-Functional Requirements

| ID | Requirement |
|----|-------------|
| NFR-01 | Indexing must not block the Obsidian UI thread for more than a few hundred milliseconds at a time (use batching or async processing). |
| NFR-02 | Embedding calls must include a per-request delay of at least 100ms to avoid overwhelming the LiteLLM proxy. |
| NFR-03 | The LanceDB database must be stored as a directory inside the vault root (e.g., `.yggdrasil/vectors.lancedb/`). |
| NFR-04 | Non-markdown files (images, PDFs, etc.) must be silently skipped during indexing. |
| NFR-05 | Empty or unreadable files must be silently skipped (logged to console, no crash). |

## Scope

### In-scope
- Vault scanning for markdown files
- Note chunking (500 tokens / 100-token overlap)
- Embedding via OpenAI-compatible API (LiteLLM → llama.cpp)
- LanceDB vector storage inside the vault
- Full reindex via ribbon icon with confirmation and progress
- Error handling for network failures, API errors, and file read errors

### Out-of-scope
- Incremental indexing (add/modify/delete individual notes)
- Search/query functionality (will be PRD 001.02)
- User configuration UI for endpoint/model settings
- Support for non-markdown attachments (PDFs, images)
- Metadata filtering or faceted search
- On-device embedding (local model)

## Context

Yggdrasil is an Obsidian plugin providing RAG-powered AI assistance for dungeon masters and world-builders. This is the first major feature after the initial plugin scaffold. LanceDB (`@lancedb/lancedb` v0.30.0) is already a dependency. The embedding infrastructure is a LiteLLM proxy (`http://localhost:10001`) routing to a llama.cpp-hosted embedding model (`v5-small-retrieval-Q8_0.gguf`). The existing ribbon icon currently shows a simple "Yggdrasil is ready!" notice — it will be repurposed to trigger indexing.

## Technical Specification

### Files to Create

| File | Purpose |
|------|---------|
| `src/rag/chunker.ts` | Note chunking logic (token-aware splitting with overlap) |
| `src/rag/embedder.ts` | Embedding client for OpenAI-compatible API |
| `src/rag/vector-store.ts` | LanceDB wrapper (create/open, upsert, clear) |
| `src/rag/indexer.ts` | Orchestrator: scan vault → chunk → embed → store |
| `src/main.ts` | Update ribbon icon handler to trigger reindex |

### LanceDB Schema

```
Table: chunks
  - id: string (unique, auto-generated)
  - text: string (the chunk content)
  - embedding: vector<float32> (dimension depends on model output)
  - source: string (vault-relative file path)
  - chunk_index: number (position within the source file)
```

### Embedding API Contract

- Endpoint: `POST http://localhost:10001/v1/embeddings`
- Request body:
  ```json
  {
    "model": "v5-small-retrieval-Q8_0.gguf",
    "input": ["chunk text here"],
    "encoding_type": "float"
  }
  ```
- Response: standard OpenAI-compatible embeddings response with `data[].embedding` array.

### Chunking Strategy

1. Read file content as text.
2. Split by double-newline (paragraph boundary) as primary split point.
3. Accumulate paragraphs into chunks until ~500 tokens is reached.
4. If a single paragraph exceeds 500 tokens, split by sentence boundary.
5. Each chunk stores its 100-token overlap suffix as context for the next chunk.

### Error Handling

- Network errors during embedding: skip the chunk, log error, continue with next.
- API errors (4xx/5xx): log error, continue.
- File read errors: skip file, log to console.
- LanceDB errors: show error notice, abort reindex.
- Per-request delay (100ms): applied between embedding API calls.

### Progress Reporting

- Notice is updated every N notes (e.g., every 5 notes) with format: `"Indexing: 15/120 notes"`
- Final notice: `"Indexing complete: 120 notes indexed"` or `"Indexing failed: <error message>"`
